Active-Binary Baseline Summary (v0-v3)

Four locked baseline variants for target_future_shot_10s on the real active-defensive-action dataset, using the canonical match-grouped split and the 32-feature post-lock active feature set. Replaces the retired, fixture-scale pre-lock b0-b8 classification outputs.

1. Feature set

32 of the 34 locked ACTIVE features from src/eda/feature_config.py (6 categorical + 9 boolean + 12 continuous + 7 discrete = 34), excluding:

  • nearest_defender_distance — known self-reference bug (≈73.6% of rows ≈0m per the distribution atlas), not a genuine defensive-distance signal.
  • defenders_within_5m — confirmed substitutive/nested with defenders_within_10m for this target (reports/eda/FEATURE_INTERACTION_ANALYSIS.json: "defenders_within_5m x defenders_within_10m → substitutive").

Verified programmatically at training time (an assertion in scripts/train_active_binary_baseline.py fails the run if the count drifts from 32): 6 categorical (one-hot), 9 boolean (passthrough), 11 continuous + 6 discrete = 17 numeric (median-impute + standard-scale). None of the 5 pre-lock-dropped columns (action_x, action_y, action_zone, action_family, position_group, distance_to_center_line) appear anywhere in this feature set.

2. Split

The canonical, frozen match-grouped split in outputs/models/splits/match_assignment.json (5-fold, seed 42, computed once by scripts/compute_canonical_split.py). No fresh random split was created anywhere in this run. Train+val: 45,408 rows / 92 matches. Held-out test: 10,660 rows / 23 matches.

Per-fold average precision mean ± std: v0 0.0792 ± 0.0069; v1 0.3531 ± 0.0176; v2 0.3389 ± 0.0163; v3 0.3349 ± 0.0148. Full per-metric fold mean/std for every variant is in outputs/models/comparisons/active_binary_baseline_comparison.csv.

PR-AUC ranking: v1 > v2 > v3 > v0. The plain unweighted logistic regression (v1) has the best PR-AUC of the three fitted variants in cross-validation. class_weight="balanced" (v2/v3) buys a very small ROC-AUC gain (+0.001) at a large calibration cost: calibration intercept collapses from -0.05 (v1) to -2.43 (v2/v3) and expected calibration error jumps from 0.004 to 0.285 — balanced weighting inflates predicted probabilities well past the true positive rate, roughly tripling log loss and Brier score. This is the expected mechanical effect of balanced class weighting on a linear classifier's raw probabilities, not a broken model — but v2/v3's predict_proba output should not be read as a calibrated probability without a separate calibration step (out of scope here).

Does v3's interaction terms beat v2 by enough to matter? No. v3's PR-AUC (0.3331 CV / 0.3572 held-out) is slightly below v2's (0.3376 CV / 0.3594 held-out) both in cross-validation and in the held-out readout. ROC-AUC is statistically indistinguishable (0.8186 vs 0.8188 CV). The two largest interaction coefficients are defenders_within_10m × phase_label_settled_mid_block_proxy (+0.191) and × phase_label_wide_defending_proxy (-0.171), consistent in direction with the documented "strongest slice-level interaction" finding — but the net effect on this linear model's ranking is a wash to a small regression, not an improvement. This doesn't contradict the underlying interaction finding (established via direct stratified rate analysis, not a linear model's coefficient) — it means a simple product term added to an already class-weighted linear model doesn't translate that finding into a better-ranking baseline here.

Flagged — no clear univariate support

nearest_attacker_distance carries a moderately large v2 coefficient (+0.226) despite active_numerical_target_atlas.json documenting "no-clear-pattern" (rho=0.023) for it univariately. flag Most plausibly picking up a multivariate/correlated-feature effect rather than a real univariate relationship — worth a VIF/partial-dependence follow-up before trusting it in isolation.

Overall: 6/11 checked features have linear-model coefficients that agree in sign with their documented monotonic pattern; the other 5 either have a genuinely non-monotonic (U-shaped) documented pattern that a linear logistic term structurally cannot capture, or (for nearest_attacker_distance) show a coefficient not well-supported by the univariate atlas evidence. This is an honest limitation of a linear baseline, not a bug — a non-linear baseline (e.g. the existing hist_gradient_boosting_classifier variants in configs/models.yaml) would be needed to capture the U-shaped relationships directly.

8. Deviations from instructions

configs/models.yaml left untouched. Its classification.variants (b0_constant ... b8_interpretable_reduced) are the actual source of the retired outputs/models/classification/b* artifacts — not src/dax/models/baseline_logistic.py's default_variant_specs(), which the task background attributed them to. Investigation found default_variant_specs() was dead code exercised only by two test files and an already-archived src/dax/models/archive/specs.py — it never fed the real training entrypoint (scripts/train_models.py → dax.models.training.train_logistic_models, which reads configs/models.yaml via feature_contracts.py). Editing configs/models.yaml would have been destructive to unrelated, working functionality: b5_360_geometry/b7_full_with_360 (real-scale, 56,024 rows/115 matches, not toy-scale) and r4_full_with_360 feed the two-part xG hurdle-model sensitivity analysis, and tests/test_model_workflow_production_fixture.py asserts against b5_360_geometry/b0_constant directly.

Part B outputs are not git-tracked. Comparison CSVs, per-variant JSON/joblib and charts under outputs/models/** follow this repository's existing .gitignore convention (that whole tree is ignored except outputs/models/splits/match_assignment.json, and the retired b0-b8 artifacts were likewise never tracked). They're reproducible with a single command: python scripts/train_active_binary_baseline.py.
