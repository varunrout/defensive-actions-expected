# Active-Continuous Baseline Summary (c0-c1)

Target: `target_future_xg_10s` (the continuous, shot-conditional counterpart of the active-binary
leg's `target_future_shot_10s`). Dataset: `data/features/player_defensive_actions.parquet`, filtered
to the 4,368 rows where `target_future_shot_10s == 1` (reconfirmed directly against the real
parquet, not the rough chat estimate carried into the task brief -- matched exactly). This is this
leg's Rung 0: one dummy floor (`c0_dummy`) and one real candidate (`c1_lognormal_glm`), mirroring the
binary legs' own Rung 0 discipline (Prompts 36/49).

*For the full math behind the models this leg reuses (logistic regression, gradient boosting,
calibration), see [`../MATH_BEHIND_IT.md`](../MATH_BEHIND_IT.md).*

## 1. Why a hurdle architecture, not a single regression

Two rough analyses (done directly in chat, cited here since they are not yet committed elsewhere in
this repo) settled the two open questions this leg's design depends on.

**Distribution shape.** `target_future_xg_10s`'s shot-conditional distribution (the 4,368 rows where
a shot did follow) is heavily right-skewed (skew ~3.2-3.3, excess kurtosis ~13-14) and, critically,
**not bounded at 1** -- reconfirmed directly against the real data: **7 of the 4,368 positive rows
have `target_future_xg_10s > 1`** (max observed: 1.239). This happens because the target sums xG
across *every* shot in the 10-second window, not one shot's probability -- a possession with two
good chances in the window can exceed 1.0 even though no single shot's xG can. This single fact
rules out beta regression outright (beta regression requires the target to live in (0,1)) and makes
a single Tweedie regression across all rows a worse fit than treating "does a shot happen" and "how
much xG, given it does" as two separate, differently-shaped problems. Log-normal was the
best-fitting family among log-normal/gamma/weibull/beta for the positive-row distribution. This is
why this leg is built as a **two-part ("hurdle") model**: reuse the already-promoted binary
classifier for `P(shot)`, and fit a new regression only on the shot-positive rows for
`E[xg | shot]`, on a log scale.

**Window length -- an accepted, documented limitation, not an open question.** A separate
sensitivity check (25-match sample, real `add_future_shot_target`/`add_future_xg_target` code from
`dax.targets.short_horizon`, horizons 5/10/15/20/30s plus an uncapped possession-bound run) found
the existing 10-second window captures only ~41% of possessions that eventually produce a shot
(median time-to-shot, within a possession that does produce one: 14 seconds -- past the 10s cutoff
more than half the time). Widening the window to a full possession-bound framing was checked and
found worse, not better: some possessions run 60-390+ seconds, well past the point where the
original action's own features remain a fair predictor of the eventual outcome. **Varun's explicit
decision: keep the existing 10-second window.** It stays causally tighter even though it
under-captures real outcomes. This baseline does not revisit that decision -- it is stated here as
an accepted limitation this leg's numbers should be read alongside, not something this prompt
attempts to solve.

## 2. Confirmed inputs

**Classifier half, reused exactly, never retrained.** `v1e_gradient_boosting_calibrated` --
confirmed as the active-binary leg's actual promoted standing reference model directly against
`ACTIVE_BINARY_MODEL_LADDER.md`'s own status banner (Prompt 46), not assumed from the task prompt's
own (correct, in this case) claim. Artifact confirmed on disk at
`outputs/models/classification/v1e_gradient_boosting_calibrated.joblib`. No saved held-out
prediction array existed for it (Prompt 45/46 only persisted chart PNGs, not the raw scores), so its
held-out score here was regenerated by loading the saved model and scoring through a freshly-fit
(cheap, deterministic) `RFDesignMatrixBuilder` -- the identical reuse pattern already verified to
reproduce an original held-out score exactly in Prompt 52.

**Feature set.** The same 32 locked ACTIVE features as the binary leg (6 categorical, 9 boolean, 17
numeric -- `nearest_defender_distance` and `defenders_within_5m` already excluded per
`train_active_binary_baseline.py`'s own docstring). No new features added, none removed -- nothing
in this leg's own data forced an exclusion.

**Positive-row structure.** 4,368 of 56,068 rows. Split via the canonical match-grouped assignment:
3,600 rows / 92 matches in train+val, 768 rows / 23 matches in held-out test. Per-canonical-fold
positive-row counts: fold 0 = 758, fold 1 = 830, fold 2 = 631, fold 3 = 753, fold 4 = 628. **No fold
has fewer than 100 positive rows** -- this leg's sample is much smaller than the binary legs'
(thousands of positive rows here vs tens of thousands of rows there), but every fold clears a
reasonable stability floor; none is flagged as dangerously thin.

## 3. Rung 0 variants

| Variant | Model | Notes |
|---|---|---|
| `c0_dummy` | `DummyRegressor(strategy="mean")` on `log1p(xg)` | training-fold mean of `log1p(xg)`, back-transformed via `expm1` for original-scale reporting |
| `c1_lognormal_glm` | `LinearRegression()` on `log(xg)` | natural log (every positive row has `xg > 0` by construction, reconfirmed: 0 rows `<= 0`), same 32 locked features, same `DesignMatrixBuilder` preprocessing as the binary leg (imported directly, not reimplemented) |

`c0` and `c1` are fit on different log transforms by this leg's own design (`log1p` for the dummy
floor, natural `log` for the real candidate) -- **their own "native" log-scale RMSE/MAE numbers are
therefore not directly comparable to each other** (`log1p(0.05) = 0.049` vs `log(0.05) = -3.0` are
not the same kind of number). Section 4 below makes this explicit and uses a **common-scale**
metric (natural log of both variants' back-transformed xg-scale predictions) for the actual
head-to-head comparison, rather than the misleading native numbers.

## 4. Cross-validation results (5-fold, OOF metrics)

| Variant | Common-scale log RMSE | Common-scale log MAE | Naive MAE (xg scale) | Corrected MAE (xg scale) | Naive R² | Corrected R² |
|---|---|---|---|---|---|---|
| `c0_dummy` | 1.1409 | 0.9437 | 0.0837 | 0.0837 | -0.0040 | -0.0040 |
| **`c1_lognormal_glm`** | **1.0014** | **0.7914** | **0.0721** | 0.0823 | -0.0473 | **0.0294** |

`c1` beats `c0` on the fair common-scale log RMSE/MAE, on original-scale naive MAE, and on
corrected R² (the only metric where `c0` isn't already at its ceiling -- `c0`'s naive/corrected
columns are identical since a constant prediction has no meaningful log-normal correction to
apply). `c0`'s R² is slightly negative (predicting the training-fold mean is *worse* than predicting
the overall mean on this held-out-fold split, an expected small-sample-CV artifact, not a bug).
`c1`'s naive R² is also negative (-0.047) despite `c1` clearly ranking rows better than `c0` --
resolved in section 5 below (the back-transform, not the ranking, is the problem there).

## 5. Two back-transforms: naive `exp(pred)` vs log-normal-corrected `exp(pred + σ²/2)`

Exponentiating a log-scale prediction directly (`exp(pred)`) recovers the **median** of the implied
log-normal distribution, not its mean -- and `E[xg]` is what the downstream hurdle combination
(section 7) actually needs, since `target_future_xg_10s` is itself a sum/expectation-type quantity.
By Jensen's inequality, `E[exp(X)] > exp(E[X])` for any non-degenerate random variable `X`, so the
naive back-transform **systematically under-predicts the true conditional mean**. The standard
log-normal correction, `exp(pred + σ²/2)` (`σ²` = the fitted model's own training-fold residual
variance on the log scale), corrects for this.

Real numbers, `c1`, held-out test: fitted `σ² = 0.934` (large, consistent with the heavy log-scale
residual spread this target's skew/kurtosis implies), giving a mean correction factor
`exp(0.934/2) ≈ 1.60` -- the corrected prediction runs about 60% higher than the naive one on
average.

**Which one should the hurdle combination use, and why**: the **corrected** back-transform.
Naive `exp(pred)` has a *lower* MAE here (CV: 0.0721 vs 0.0823) -- but MAE is minimized by the
**median**, and naive `exp(pred)` is approximately a median-type estimator, which is exactly why it
wins on MAE despite being a biased estimator of the mean. R² and RMSE-type metrics, which are
about matching the **mean**, tell the opposite story: `c1`'s naive-back-transformed R² is negative
(-0.047, worse than predicting the constant training mean), while `c1`'s corrected R² is positive
(+0.029, genuinely better than the constant-mean floor). Since the hurdle combination
(`P(shot) * E[xg|shot]`) needs an unbiased estimate of the conditional **mean**, not the median, the
corrected back-transform is used for that purpose throughout this document and in
`hurdle_pipeline_readout.json` -- reported honestly alongside the naive numbers rather than only
quoting whichever one looks better.

directional fault either.

## 8. Paired significance test, `c1` vs `c0`

Common-scale log RMSE, per canonical CV fold (`outputs/models/validation/significance_c0_vs_c1.json`):
`c1` beats `c0` in **5 of 5 folds** (mean diff -0.1394, i.e. `c1`'s RMSE is lower). Paired t-test
t=-11.04, **p=0.0004** -- significant at the conventional threshold. Wilcoxon signed-rank p=0.0625,
the same 5-fold floor (the minimum p-value achievable with 5 same-signed paired samples) seen
throughout this project.

**Read cautiously**: this leg's per-fold sample (628-830 positive rows) is much smaller than the
binary legs' (tens of thousands of rows per fold). The test result is reported plainly, not
suppressed, but the same honest caveat applies here as to every small-n significance test elsewhere
in this project -- directionally informative, not strong statistical proof on its own. That said,
5/5 folds agreeing in direction, combined with the held-out readout confirming the same ranking, is
a real, multi-angle-consistent signal, not a single fragile number.

## 9. Full hurdle pipeline readout (diagnostic, not the Rung-0 gate)

`P(shot)` (from `v1e_gradient_boosting_calibrated`, reused unchanged) times `E[xg|shot]` (from
`c1_lognormal_glm`, corrected back-transform), computed for **every** held-out test row (10,660
rows, not just the positive ones), compared against the real `target_future_xg_10s`
(`outputs/models/validation/hurdle_pipeline_readout.json`):

| | RMSE | MAE | R² |
|---|---|---|---|
| Hurdle pipeline (`P(shot) x E[xg\|shot]`) | **0.0449** | **0.0119** | **0.1426** |
| Trivial baseline (unconditional train-set mean of `target_future_xg_10s`) | 0.0485 | 0.0150 | ~0.0000 |

The two-part architecture beats the trivial constant-mean baseline on every metric -- a real,
positive first read on whether combining the two already-separately-validated halves actually works
end to end. **This is explicitly a diagnostic, not the Rung-0 gate**: the Rung-0 promotion decision
for this leg rests on the regression-only `c1`-vs-`c0` comparison (sections 4/8 above), since that
is the piece this prompt actually built and can fairly gate; the classifier half was already gated
and promoted on its own leg.

## 10. Rung-0 result

**`c1_lognormal_glm` clears Rung 0** against the `c0_dummy` floor: consistent direction across CV
and held-out test, on the fair common-scale log metric and on original-scale MAE/R², with a
statistically significant (if small-n-cautioned) paired test, and a positive first end-to-end hurdle
readout against a trivial baseline. No model ladder is built in this document -- this is Rung 0
only, mirroring the binary legs' own Prompt 36/49 discipline; ladder rungs (quadratic/interaction
terms, random forest, gradient boosting, mirroring the binary legs' Rungs 1-4) are Prompt 55+, after
this Rung 0 is reviewed.
